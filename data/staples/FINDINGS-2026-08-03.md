## 1. riftdecks is behind a standing Cloudflare challenge, not "intermittent bot detection"

README step 1 says to retry a plain GET 2–3× with a delay. That can never work. Every request
returns HTTP 403 with `cf-mitigated: challenge` and a "Just a moment..." interstitial requiring
JavaScript execution. Confirmed with both a plain fetch and curl sending the exact browser
User-Agent `fetch_legend_stats.py` uses.

A real browser (Playwright driving installed Chrome, headful) *does* get through and banks a
`cf_clearance` cookie — but Cloudflare re-challenges aggressively after a handful of
navigations, so bulk scraping is not viable. Manual page capture is the practical route.

## 2. The URL pattern in sources/urls.md is wrong

Not `https://riftdecks.com/legends/{slug}/stats`. The real shape is:

    https://riftdecks.com/legends/constructed/{slug}?metagame_id={N}

with `metagame_id=4` = Vendetta (current), `3` = Unleashed, `2` = Spiritforged.

## 3. Legend stats pages default to Vendetta, and Vendetta is tiny

The live Irelia page reports **41 decks / 48 cards**, not the 1,492 in legends.csv. Those

winrate 53%, Tier 1.

METHODOLOGY §4 asked whether Vendetta had grown enough to use. Answer: it has gone 29 → 41

## 4. fetch_legend_stats.py's parser cannot be fixed by tweaking the regex

The card name is not in the row's text at all. A row's `innerText` is exactly
`CORE | ×3.0 | 100% | 1.00x`. The name lives in the row's `<img alt>` and its
`/cards/details-{slug}` href. Any regex over flattened text therefore captures the *next*
row's name — an off-by-one across the entire table, plus a dropped first row.

Extract from the DOM instead. Bonus: the href yields the real card slug, which removes the
guesswork in `card_types.csv` (slugify-by-hand is currently unverified for 136 of 137 cards).

## 5. /staples is usable, but only after correcting the metric

riftdecks' own definition of Popularity:

> the number of decks that have included it in the past 30 days ... divided by 30 ... We use
> the most popular card as a 100% popularity benchmark, and all other cards are adjusted in
> percentage based on this reference.

The `/30` is a constant and cancels in the ratio, so the metric reduces to

    popularity(X) = decks_containing(X) / decks_containing(most_popular_card)

That is **one global denominator shared across all six Domains** — structurally the same error
as the meta-wide play rate the whole project exists to avoid. Calm Rune is the benchmark, so
Calm cards read approximately correct by accident while every other Domain is deflated.
Measured: **Fury Rune tops out at 46.26%**, not 100%. The domain filter does *not* re-normalise.

**The correction.** Every deck of Domain D runs D Runes, and no deck outside D legally may, so
the Rune's popularity is precisely D's share of the benchmark. Dividing cancels the global
denominator:

    inclusion(X, D) = popularity(X) / popularity(D_Rune)

This lands on METHODOLOGY §1's definition of "decks of Domain D" — decks whose Legend identity
contains D — with no extra work.

Worked from the captured Fury page: Falling Star 35.93/46.26 = **77.7%**, Noxus Hopeful
**71.7%**, Ferrous Forerunner **70.5%**, Kai'Sa Survivor **55.1%**.

Cross-check on Calm, where the correction is a no-op: Defy 99.52/100 = **99.5%**, matching the
99.5% `aggregate.py` derives from per-Legend Unleashed data by a fully independent route.

Implemented in `scripts/parse_staples.py` (`--selftest` reproduces the Fury figures above).

### What this approach cannot do

- **Unleashed.** /staples is a rolling 30-day window, so it only ever describes the current
  format. Per-Legend pages with `metagame_id=3` remain the only route to Unleashed.
- **Dual-Domain cards.** Their denominator is the *intersection* of two Domains, which no
  single Rune supplies. Report separately; do not normalise.
- **Colorless cards.** No Rune, legal anywhere. Excluded per METHODOLOGY §6.
- **Type filtering.** /staples mixes Units, Gear, Runes and Spells with no type filter.
- Slight upward bias: a deck could hold D in identity yet run zero D Runes. Rare, but it
  shrinks the denominator, so treat results as a mild over-estimate.

## 6. riftools.app is not the easier alternative it looks like

Reachable without Cloudflare, but its per-Legend view (`/legend-breakdown`) is fully
client-rendered — plain curl returns "Loading legend data." — so it needs the same browser
machinery. And the sample is smaller: **Irelia, Set 4, 32 decklists / 80 matches**, with
individual matchups at 2–4 matches. Its card-stats table also uses the all-decks denominator
and truncates around 22.9%.

Useful for one thing: a clean Legend roster. It supplied correct subtitles including
**Annie, Dark Child** and **Draven, Glorious Executioner** — the Fury-primary anchors urls.md
listed as missing.
